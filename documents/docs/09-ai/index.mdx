A CityParquet package is static files queried with SQL, which an agent can
work with unaided. What an agent lacks is knowledge. It does not know what
the format guarantees. It does not know which DuckDB functions exist: without
help it reaches for `ST_Volume` and `LOAD spatial`, and a query built from
those fails. Two pieces close that gap. Both live in the
[`cityjson/cityparquet`](https://github.com/cityjson/cityparquet) repository,
under `ai/`.

The two work separately. The server alone gives an agent the documentation
and an engine. The skills alone give it correct SQL to run in DuckDB v1.5.5
with the `cityjson` and `three_d` extensions installed and loaded. Together,
the skills tell the agent which server tool to call and when.

## What an agent can then do

- Answer questions about the specification by quoting it, not by
  recalling it: which columns are reserved, how semantic surfaces are stored,
  what a package must contain.
- Describe an unfamiliar dataset in one call: its module tables, row counts,
  LoDs, geometry columns and coordinate reference system.
- Query a package over HTTPS without downloading it, and measure it: volumes
  gated on solid validity, footprints counted once per building, heights per
  building rather than per part.
- Build, edit and write packages, and convert them to CityJSON, CityJSONSeq
  and FlatCityBuf, keeping the coordinate reference system on the way out.

## Status

:::note[Local, or hosted and read-only]
The server runs on your machine over **stdio**, from a clone of the
repository, where it can read and write your own files. It also runs as a
**hosted, read-only endpoint** over streamable HTTP on Google Cloud Run,
sandboxed and limited to the project's own data hosts;
[MCP server](/ai/mcp-server) describes both. The skills install as a Claude Code plugin or through APM,
but they do not start the server; you register it yourself.
:::

Everything here targets **DuckDB v1.5.5** and the `cityjson` and `three_d`
builds published for it in the DuckDB community repository. Older DuckDB
versions install older builds of both extensions, which lack most of what the
function references describe.
