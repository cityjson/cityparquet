# CityGML CM naming audit — CityJSON-derived names in the specification

**Status:** #1–3 and S1–S6 decided on 2026-10-03; the specification and documentation updated the same day (see Decision). #4–13 remain proposals. Recorded 2026-10-03 while revising the paper (§3 Design), where the prose said "implicit geometry" but the format still said `geometry_templates`.

**Principle:** CityParquet encodes the CityGML 3.0 conceptual model, not CityJSON. Names should follow the CityGML CM where the CM has a term; CityJSON names belong only in the encoder/decoder mapping (`07-mapping-cityjson.mdx`). Several names in the specification are CityJSON's instead. This list records them so a rename can be decided in one pass. The paper must match whatever the specification says, so the paper changes only after the specification does.

Line references are to `documents/docs/03-specification/` at commit `e0ba044`.

## Related open issue

The CityGML 3.0 CM, Requirement 2 (`/req/core/isorestrictions`), says solids "SHALL only include exterior boundaries". `geometry_properties.shells` admits interior shells. Decide whether interior shells are a CityGML 2.0 / CityJSON source feature that CityParquet carries beyond the 3.0 CM, and say so in `03-geometry-semantics` (the paper has the same open question in §2 and §3.3). **Resolved as S3:** interior shells are kept as a stated departure; `03-geometry-semantics` now says so.

## Decision (2026-10-03)

The author decided #1–2: the sidecar becomes `implicit_geometries.parquet` and the column `implicit_geometry`. The paper (`03-design.typ`: package figure, reserved-columns table, §3.4) already uses the new names, ahead of the format. Still open: field names inside the struct (`point` → `reference_point`; `transformationMatrix` style).

The author also decided the extension scheme (S4–S6): every name an extension adds carries a short namespace as a prefix (`energy_heatCapacity`, `energy_PartyWallSurface`, `energy_ThermalZone`, `energy_building_physics.parquet`), and `city.extensions` is keyed by namespace and references the schema document by URL (`name`, `url`, `version`, `xmlns`) rather than embedding it.

**What landed on 2026-10-03:**

- The specification (`01`, `02`, `03`, `04` retitled "Appearance & implicit geometries", `05`, `06` rewritten to the namespace scheme, `07`, `08`, index), design decisions 02, 04 and 06, the open questions, the software page and the tutorials use the new names and the CityGML 3.0 vocabulary (implicit geometry, relative geometry, reference point, transformation matrix). "Template" survives only as a CityJSON member name on the mapping page.
- Namespace derivation: the CityJSON `extensions` member key (or the ADE's XML-namespace prefix) lower-cased with every character outside `[a-z0-9]` removed; the namespace must match `^[a-z][a-z0-9]*$` and be unique in the package. A core name beginning with a declared namespace and `_` is a hard error, as is an extension module whose file name equals a core module's.
- The real Energy ADE 3.0 (beta 7) replaces the invented `SolarPanel`/`Thermostat` example.
- Interior shells (S3) are stated as a departure from CityGML 3.0 Requirement 2.
- The rename sites outside the two implementation libraries: the root and CityLake `CLAUDE.md`/`AGENTS.md`, the agent skills, the MCP server's `SIDECAR_TABLES` (corpus regeneration pending), CityLake's `SIDECAR_TABLES`, the benchmark comments and `test/TESTING.md`.
- `cityparquet-rs` and `duckdb-cityjson` are updated in parallel.

**Still open:**

- Field names inside `implicit_geometry` (`point` → `reference_point`; camelCase `transformationMatrix` vs snake_case). Unchanged for now.
- Attributing `+` names when one CityJSON source declares several extensions: needs the extensions' schema documents (`extraAttributes`, `extraCityObjects`, `extraSemanticSurfaces`). Both implementations derive the namespace from a single declared extension only; `cityparquet-rs`'s extension registry stays a stub, so an extension class without a core-class name has no resolvable module.
- Full ADE object-class metadata.
