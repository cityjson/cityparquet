#
# Source: the city3d STAC catalogue at
#   https://storage.googleapis.com/city3d-stac/catalog.json
# 53 collections; 33 publish items, 20 publish only a collection.json (no items,
# therefore no downloadable URL) and are skipped entirely.
#
# Generated: 2026-08-15. Every URL below was verified live on that date
# (HTTP status + size via HEAD, or a ranged/streamed GET where the origin
# rejects HEAD or omits content-length). Sizes are the on-the-wire bytes of
# the download itself (compressed size for .zip / .gz).
#
# Usage — the usable list is exactly:
#   grep -v '^#' bench/catalogue_benchmark_urls.txt
#
# Ordering: smallest and quickest first, multi-gigabyte last, so the list can be
# truncated at any point and still give a spread of formats and geographies.
#
# Sampling: single-item collections contribute their one URL. Large collections
# contribute a small representative sample (Amsterdam for netherlands-3d-bag,
# Tokyo for japan-plateau-3d, Manhattan for american-cities-3d). japan-plateau-3d
# is sampled by CityGML *module* rather than by volume, so the corpus covers a
# spread of CityObject types (buildings, roads, bridges, vegetation, city
# furniture, land use, terrain, ...) rather than 15 building tiles.
#
# CONVERTER SUPPORT: the CityParquet converter currently cannot read CityGML 1.0
# or 3.0, CityJSON 1.0, or geographic (degree-valued) CRS. A SECOND blocked
# section lists CityGML modules whose 1st-level CityObject types the reader does
# not map — valid, ingestible-looking files that would otherwise yield a
# silently truncated (often zero) object count. Collections known to
# be blocked on one of those grounds are listed in the "BLOCKED" section at the
# very end with their URLs COMMENTED OUT. They are valid CityGML/CityJSON and are
# retained as a conformance corpus; uncomment them once the reader supports them.
# The default grep above therefore yields only data the converter can ingest today.

# BLOCKED — CityGML modules whose 1st-level CityObject types the CityGML
# READER DOES NOT MAP. Valid CityGML 2.0, downloadable, readable by other
# tools; URLs deliberately commented out so the default grep skips them.
# ---------------------------------------------------------------------------
#
# The reader (crates/cityparquet/src/citygml/reader.rs) streams bldg:Building
# plus a fixed list of 1st-level non-building types (WaterBody, LandUse,
# CityFurniture, SolitaryVegetationObject, PlantCover, Bridge, Tunnel,
# GenericCityObject, CityObjectGroup, Road, Railway, TransportSquare). A
# cityObjectMember of any OTHER type is skipped.
#
# For the converter that is a partial ingest. For a BENCHMARK it is worse: the
# readbench `citygml` runner used to report `count = 0`, exit 0, in a fraction
# of a real read's time — while every other format's artefact for the same tile,
# produced by citygml-tools, reported N (citygml-tools maps dem:ReliefFeature to
# CityJSON TINRelief, which this repository treats as first class and writes to
# relief.parquet). The runner now REFUSES such a document outright, naming the
# offending types, so these tiles cannot be measured at all until the reader's
# type map is extended.
#
# PROVENANCE OF THE FIGURES BELOW: the lsld, trk, urf and ubld tallies were
# MEASURED on 2026-08-16 by downloading each tile and running
# `cityparquet-readbench --child --format citygml --scenario count`. The dem
# entry is INFERRED, not measured — the tile is 599 MB and was never downloaded;
# dem:ReliefFeature is unmapped by explicit decision in the reader's own type
# map (crates/cityparquet/src/citygml/reader.rs, the ReliefFeature comment in
# `citygml_object_type`), so the refusal follows by construction rather than
# from a run.
#
# Do not re-admit these to the USABLE list without either extending the reader's
# 1st-level type map or converting the tile with citygml-tools first.
